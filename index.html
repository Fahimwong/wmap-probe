T1 · baseline

Calls the allowlisted Router only. Touches nothing else. If this fails, the setup is wrong — stop.

T2 · internal call to a NON-allowlisted contract

Router → dynamic Curve. No tokens move. This isolates the single most important question: are internal calls checked?

T3b · BUY via standard approve

approve WLD → Router, then Router → dynamic Curve → dynamic Token to you. Spends 0.05 WLD.

T4b · SELL via standard approve (the key test)

approve on the dynamic token → Router → Curve → WLD back. The approve's to is the dynamic token, so this is where the entrypoint rule bites.

T3 · BUY via Permit2

Only needed if T3b failed. WLD is allowlisted, so this should pass if Permit2 works at all.

T4a · SELL via Permit2

Only needed if T4b failed. Uses Permit2 on the dynamic token, which is not in the Permit2 list.

T4c · SELL via EIP-2612 permit

Only needed if T4a and T4b both failed. The dynamic token is touched only internally. Two steps: sign, then send.
